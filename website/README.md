# Arceo — marketing website

The public marketing site for Arceo (cost and risk forecasting for AI agents).
Self-contained Next.js app: no database, no auth. The one server-side feature
is the demo-request form (`app/api/demo-request/route.ts`), which posts leads
to a Slack webhook you configure.

## Stack

- Next.js 16 (App Router, Turbopack), React 19, TypeScript
- Tailwind CSS v4 via PostCSS, plus hand-written CSS on design tokens (`app/globals.css`)
- `motion` for animation
- Fonts are fetched from Google Fonts at build time (`next/font`)

## Run locally

```bash
npm install
npm run dev        # http://localhost:3000
```

## Deploy

Any Node host that runs Next.js works. The two easy paths:

**Vercel:** import the repo/folder, framework auto-detected. Set the
environment variables below in Project Settings before the first build.

**Bare Node:**
```bash
npm ci
npm run build
npm start          # serves on $PORT or 3000
```

Health check: `GET /` returns 200. There is no separate health endpoint.

## Environment variables

See `.env.example` for the full annotated list. Summary:

| Variable | When | Purpose |
|---|---|---|
| `NEXT_PUBLIC_SITE_URL` | build | Canonical origin for sitemap/robots/OG URLs. Set to the real domain. |
| `ARCEO_DEMO_WEBHOOK` | runtime | Slack-compatible webhook that receives demo-request leads. **Without it, leads land only in server logs.** |
| `NEXT_PUBLIC_APP_URL` | build | URL of the Arceo dashboard app. Unset on production builds hides the "Sign In" link (intended while no hosted app exists). |
| `ARCEO_CONTACT_EMAIL` | runtime | Fallback contact email if the form cannot deliver. |
| `BACKEND_URL` | runtime | Target for the `/api/backend/*` rewrite. Marketing pages do not use it; safe to leave unset. |

`NEXT_PUBLIC_*` values are inlined at **build** time — changing them requires a
rebuild, not a restart.

## Things worth knowing

- `app/opengraph-image.tsx` and `app/apple-icon.tsx` generate images at request
  time via `next/og`; no assets to manage.
- The `pageshow`/reload handlers in `components/Hero.tsx` and `lib/useFadeIn.ts`
  fix a Safari/Chrome back-navigation bug where faded-in content sticks at
  opacity 0. Do not remove them.
- `AGENTS.md` / `CLAUDE.md` are auto-generated by `next dev` for AI coding
  agents; they are not part of the site.
- The demo-request route rate-limits per instance (5/min per IP) and has a
  honeypot field; no captcha is needed.

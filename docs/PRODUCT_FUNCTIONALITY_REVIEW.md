## What genuinely works (verified live, not just read)

- **The core loop is real end-to-end.** Signup → per-signup org (real tenant boundary) → API key → register agent → server-side risk classification ran **keyless** via the catalog/keyword layers and produced a substantive blast radius (score 51, per-action worst-case $ contributors, chain risk — computed, not canned) → captured LLM calls fed the forecaster → a BLOCK policy **actually stopped `stripe.delete_customer` before anything ran** → CFO PDF generated from live endpoints with plain-English translation.
- **The forecast engine is honest by design** (Cost Portfolio): three confidence tiers with per-input provenance (declared/measured/default), refuses to print a number with no signal (`available:false`), live capture unlocks tighter bands at real thresholds (≥5 calls feeds it, ≥50 calls/7d unlocks the tight tier). Strongest area in the codebase.
- **All 14 frontend pages hit real backend APIs — zero mock rendering.** `mockSpend.ts` is just a leftover type name.
- **Live simulation is a real multi-provider LLM agent loop** (claude/gpt/gemini/deepseek/grok/ollama, up to 20 tool-calling turns) through the **real** in-process enforcement engine; sim token usage genuinely feeds the forecaster's medium tier. The fail-open→fail-closed sim bug is fixed and regression-tested.
- **Test discipline is real:** 183 backend tests green on real Postgres in CI, with genuinely adversarial coverage (fail-closed, deny-by-default, cross-org, enforcement precedence, vault crypto).

## 🔴 STILL OPEN on current dev — the actionable list (prioritized)

These are verified present at `dev@549b388`. Ordered by leverage.

1. **No hosted/staging instance anywhere** — the single biggest gap. Everything runs on localhost; `docker-compose.yml` has only Postgres + Redis (no app service), so `docker compose up` does **not** launch the product. The single-container Dockerfile is real and boots cleanly, but there's nothing deployed. This one gap simultaneously blocks the CIO demo, any pilot, and the roadmap's own Phase-2 "in staging" exit criterion. *(P0)*
2. **SDK quickstart silently captures nothing.** `sdk/README.md:128` still says "capture is unauthenticated," but the capture endpoint requires `X-API-Key` (`backend/main.py:2740–2750`) and the SDK swallows the 401. A pilot following the docs gets an empty dashboard and concludes the product is broken — worst failure mode because it's invisible. Tiny fix (doc + require key in quickstart). *(P0)*
3. **Every in-product integration snippet points at the fictional `api.arceo.io`** — hardcoded in `Settings.tsx`, `AgentDetail.tsx`, `Authority.tsx`. A prospect copy-pastes a snippet that can't resolve. *(P0, unblocked by #1)*
4. **No UI to mint the API key that half the product requires.** `/api/keys` CRUD is fully implemented and gates the proxy, capture, enforce, and scan — but zero frontend references it; keys are curl-only. *(P1)*
5. **Ingestion is one SDK deep; imports discard token usage.** No OpenTelemetry receiver anywhere. LangSmith/Langfuse/generic importers normalize only tool/action/params — **no token/usage fields survive** (`backend/ingestion/base.py`), so a prospect's months of observability history feed risk analysis but **never the spend forecast**, which is the validated CIO pain. No polling/webhooks/stored creds either. *(P0 for pilots)*
6. **Budgets alert but never enforce.** Budget CRUD, budget-fit, anomaly detection, and Slack alerts all work — but nothing in `enforcement.py` converts "budget exceeded" into a throttle/block/require-approval. The CIO pain is spend *control*, not spend observation. Wiring budgets into enforcement is the one sentence no observability competitor can say, and it unifies Arceo's two halves. *(P1, high strategic value)*
7. **Read-prefix classifier evasion (confirmed critical, still present).** `WRITE_OVERRIDE_TOKENS` (`risk_classifier.py:149`) still omits high-impact verbs — `terminate, refund, pay, wire, disburse`. So `lookup_and_terminate_stale_instances` and `check_and_refund_customer` classify as benign reads and silently drop their destructive labels; the read path never escalates to the LLM. Independent of LLM availability. Engine change — worth your review. *(P1)*
8. **Keyless silent degradation.** Without a server `ANTHROPIC_API_KEY`: `/api/scan`, code/GitHub extraction, scenario generation, red-team all 503; a non-dry "simulation" silently returns 0 steps; classification drops to keyword-only. For a demo it's a provisioning checklist item; the silent-empty non-dry sim is the sharp edge. *(P1)*
9. **Vault posture ≠ the pitch.** `ARCEO_REQUIRE_VAULT` defaults **off** (agent's own key passes upstream); covers 3 bearer-auth providers (stripe/github/sendgrid) of 10 proxied. Crypto and fail-closed-on-decrypt paths are real, but "no credential, no call" is not the shipped default. *(🟡/P2 — scope decision)*
10. **Business layer absent — cannot charge money.** No billing/metering/plans, no SSO/SAML/SCIM, no data retention/deletion story (a DPA blocker on its own), model-price catalog is hand-maintained YAML with no refresh automation. *(P1 to monetize)*

## Market / capability gap analysis

Arceo's core loop is real, not vaporware: register agent → 3-layer risk classification → policy engine (fail-closed, precedence-correct, test-verified) → enforcing proxy with vault credential injection → usage ingestion → honest 3-tier spend forecast → budget/anomaly Slack alerts → client-side CFO PDF, all green on 183 Postgres-backed tests. For the validated CIO spend-forecasting pitch, the demo is closeable today with three preconditions: a deployed instance (none exists anywhere — the single biggest gap, unblocking demo, pilot, and the roadmap's own exit criteria at once), an ANTHROPIC_API_KEY provisioned, and a script that avoids the approve button (approvals mark actions EXECUTED without executing them) and pre-decides the disclosure line for the seeded 30-day demo data. A 3-month pilot is blocked by the last-mile integration surface, not the engine: no OTel, LangSmith/Langfuse importers that discard token usage (so they never feed the forecast), no framework-level capture, an SDK quickstart that silently captures nothing due to a swallowed 401, and LLM usage audit rows mis-tenanted into the shared default org — the exact data the buyer pays for. Charging money is blocked by wholesale absence of the business layer: zero billing/metering scaffolding, no SSO and RBAC on exactly one endpoint, no data retention/deletion story, env-var key custody, fail-open enforcement defaults, and docs/versioning that would fail technical due-diligence. Scale gaps (single worker, in-process jobs, buffered streaming, no observability, 3-provider vault) are appropriately deferred. Net: a genuinely working local prototype about 4-6 focused weeks from pilot-able, with the highest-leverage moves being (1) deploy anything, (2) fix the silent-capture and tenant-attribution bugs, (3) make one integration path (the LLM base-URL proxy) the documented golden path, and (4) wire budgets into enforcement to own the 'hard spend cap' sentence no observability competitor can say.

  - Three compounding defaults: per-agent default_effect=ALLOW (unmatched dangerous actions pass), ARCEO_REQUIRE_VAULT unset means the proxy passes the agent's own credentials through ('no credential, no call' is not the shipped posture), and enforcement only governs traffic that voluntarily routes through the proxy/SDK — a direct API call is invisible.

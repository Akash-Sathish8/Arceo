## Design Specificity Verdict

PASS, narrowly — for half the app. The severity architecture (4-tier bands with documented ΔE separation, index.css:121-133), 10-label risk vocabulary with plain-English names, the Approvals decision card (provenance badge, scenario line, policy provenance, no-unit-conversion disclaimer), and the Login risk-node graph are unmistakably Arceo. But SpendDashboard/CostPortfolio/History are category-interchangeable billing-dashboard idiom, and AgentDetail — the core page — is generic 2023 Tailwind-admin that predates the token system. A renovation two-thirds complete.

## Priority Issues

- **[P0] Hardcoded admin credentials + third-party script in shipped index.html** (index.html:10-23): `admin@actiongate.io`/`admin123` in a synchronous auto-login script plus `mcp.figma.com/.../capture.js`, marked "TEMPORARY (Figma capture): REVERT after capture". Visible via View Source. Remove, and rotate the password (it's in git history).
- **[P0] Mobile (375px) app shell unusable**: sidebar (248px) never collapses; content squeezed to ~60px ("Conn", "$4,28", one word per line). Only 4 responsive utilities in 1 of 38 files. Login page is fine; the shell has no mobile behavior at all.
- **[P1] Bulk (and single) approval of irreversible actions: no confirm, no undo** (Approvals.tsx:214-252). The product's pitch is human sign-off before irreversible actions; its own most irreversible action has zero guardrails.
- **[P1] Silent failure under outage**: most pages render genuine-empty copy during 502s; "Try demo account" fails with zero feedback; Settings sections `return null` on fetch error (Settings.tsx:182-190, 260).
- **[P1] AgentDetail off-system and overloaded**: 2,982 lines, local RISK_COLORS conflicting with tokens (same label, different color+name elsewhere), 12-stat rainbow strip, 4 jobs on one scroll, zero memoization.
- **[P1] Keyboard/SR exclusion cluster**: hover-only Tooltip carries all methodology help (Tooltip.tsx:31-37); div-onClick disclosures (AgentDetail.tsx:381-384, 2655-2658); AgentDrawer never moves focus in; Login labels unassociated; 19 inline `outline:'none'` overriding the global focus ring.
- **[P1] /agents 404s** — the core fleet page lives only at `/`; the intuitive URL dead-ends.
- **[P2] Page-level inconsistency tax**: titles, gutters, button shapes, duplicate stat-tile/code-tab components; sidebar pending badge critical-red vs page pending-amber.
- **[P2] Command palette undiscoverable; also fully open pre-auth with dead clicks on login.**
- **[P2] Performance debt**: no route code-splitting (14 eager routes), History table unvirtualized + per-keystroke client filter, sidebar width animation reflows app.
- **[P2] No dark mode / no `color-scheme`; locale hardcoded en-US (time.ts, format.ts).**

## What's Working

- index.css is a design constitution: documented type-scale usage rules, AA-verified severity tiers with separate graphics rings, elevation policy, and a clever @theme remap keeping ~550 legacy utilities on-palette.
- Honest-state engineering as house style: provenance badges on seeded data, "needs data" instead of fake $0 forecasts, partial-failure toasts ("3 resumed, 1 failed — still in the queue").
- The Approvals decision card is the best screen in the app and proof the team can do task-first design.
- Drawer dialog semantics (role, aria-modal, inert, Escape, scroll lock), aria-busy skeletons, excellent empty-state copy.

## Minor Observations

Duplicate "..." vs "…" (21×), clipped chart label on Fleet Spend Forecast, duplicate error toasts on /compare, dead `.content-stripe` CSS, terminology drift (sidebar "Approvals" vs page "Approval Queue"), personal fork path in GitHub Action snippet (Authority.tsx:981), window.confirm inconsistent with inline-confirm pattern, Login rAF node graph ignores prefers-reduced-motion.

## Questions to Consider

- If Approvals is the best screen, what would the app look like if every page were held to its standard?
- Does AgentDetail need to be four jobs, or is it three pages wearing one URL?
- Is mobile a real surface for this product, or should the shell explicitly declare desktop-only and enforce a graceful floor?
